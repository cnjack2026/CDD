# CDD

CDD（Card-Driven Development，卡片式开发）是一种面向 AI 软件开发的规格方法，通过卡片组织边界明确、可实现且可验收的交付单元。项目以当前交付所需的最小设计开始编码，每轮工作保持有限上下文和可控智力负担。

一张卡片既是一份规格，也是一次开发任务：定义当前交付拥有的能力和边界，指定正式代码和测试代码的修改范围，并提供可执行测试、覆盖率阈值、修订条件和完成条件。卡片按主题目录组织为一棵树，默认卡片根目录是 `docs/`。

## 内容

| 文件 | 用途 |
| --- | --- |
| `CDD.md` | CDD 完整规范：设计哲学、README 格式、卡片格式、检查规则、完成条件 |
| `AGENTS.md` | Agent 指南：AI 修改文档与代码时遵循的原则、方法和质量要求 |

## 状态机

```text
draft ──规格确认──▶ ready ──开工──▶ doing ──完成门禁通过──▶ done
  ▲                  │              │                          │
  └──────────────────┴────修订──────┴──────────────────────────┘
```

完整的格式定义、检查规则和判据以 `CDD.md` 为准。
